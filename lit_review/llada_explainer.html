01 — Motivation

Why not just use autoregressive LLMs?

Autoregressive models (GPT, LLaMA) generate text left-to-right, one token at a time. Each token is conditioned only on what came before. This has two structural consequences:

Autoregressive (GPT / LLaMA)

Prompt: "The cat sat on"
Generate:
  p("the" | "The cat sat on")       → "the"
  p("mat" | "The cat sat on the")   → "mat"
  p("." | "The cat sat on the mat") → "."

Order: strictly left-to-right
Context: only past tokens (causal mask)

Fast at generation (KV cache works). But each token only sees its left context — cannot revise earlier tokens.

Masked Diffusion (LLaDA)

Start: [M][M][M][M][M][M]   (fully masked)
Step 1: [M][M] sat [M][M][M]
Step 2: [M] cat sat on [M][M]
Step 3: The cat sat on the [M]
Step 4: The cat sat on the mat

Order: all positions simultaneously
Context: ALL tokens (bidirectional)

Slower per-step (no KV cache). But every token sees ALL other tokens — richer context, can predict any position using full sequence context.

The key promise: By using bidirectional attention, LLaDA can predict token at position 50 using tokens at positions 1–49 AND 51–100. An autoregressive model predicting position 50 can only see positions 1–49.

Where bidirectional context wins

Tasks where the answer depends on both left AND right context:

Fill-in-the-middle: "The [MASK] is the capital of France." → Bidirectional: sees "capital of France" → "Paris" ✓ → Causal: at position of [MASK], can't see "capital of France" ✗ Infilling code: def add(a, b): def add(a, b): [MASK] → return a + b return result Long-form reasoning: later parts of the reasoning chain inform what earlier statements should have said.
02 — Forward Process (Training)

The Forward Process: Masking tokens progressively

LLaDA uses masking as the noise process. Unlike image diffusion which adds Gaussian noise, here noise = replacing tokens with [MASK].

The masking schedule

At time t ∈ [0, 1], each token i is independently masked with probability t: q_{t|0}( x_t^i | x_0^i ) = (1 - t) · δ_{x_0^i} ← stay as original with prob (1-t) + t · δ_{[MASK]} ← become [MASK] with prob t t = 0 → no masking (clean text) t = 1 → fully masked ([M][M][M]...[M])

Visual: masking at different noise levels

Same sentence, progressively more masked as t increases:

t = 0.0 (clean):
Thecatsatonthemat
t = 0.33 (light noise):
The[M]saton[M]mat
t = 0.67 (heavy noise):
The[M][M][M][M]mat
t = 1.0 (full noise):
[M][M][M][M][M][M]
Key difference from image diffusion: Image diffusion uses continuous Gaussian noise (every pixel gets perturbed). Masked diffusion uses discrete binary noise (each token is either clean or fully masked). There's no partial corruption of a token — it's all-or-nothing.

Why masking? (vs other discrete noise)

Masking (absorbing state diffusion) has a crucial property: the model always knows which positions were masked. Unlike Gaussian noise where you can't tell signal from noise, with masking you know exactly where to predict.

Other noise: replace "cat" with "xyz" (random token) → Model sees: "The xyz sat on the mat" → Model doesn't know "xyz" is noisy vs meaningful Masking: replace "cat" with [MASK] → Model sees: "The [M] sat on the mat" → Model knows: position 2 needs to be predicted

This simplification leads to a cleaner training objective and better empirical performance.

03 — Reverse Process (Generation)

The Reverse Process: Generating by unmasking

Generation runs the process backward: start from fully masked, gradually unmask until you have complete text.

One reverse step: from noise level t to s (s < t)

For each token position i, at one reverse step (t → s): Case 1: token was already unmasked (x_t^i ≠ [MASK]) → It stays unmasked. x_s^i = x_t^i (locked in forever) Case 2: token is still masked (x_t^i = [MASK]) → With prob s/t: stays masked (not yet ready) → With prob (t-s)/t: gets unmasked! Use model's prediction: x_s^i = model's predicted token at position i
Key insight: Once a token is unmasked, it stays unmasked. Tokens are "absorbed" into their final state. Only masked tokens are in play at each step. This is why it's called an "absorbing state" Markov chain.

Full generation walkthrough (T=4 steps)

Generating a 6-token response. Green = unmasked (final), purple = still masked, orange = just unmasked this step.

Step 0 — Start (t=1.0, all masked):
[M][M][M][M][M][M]
Step 1 — t=0.75→0.5, model predicts all, unmask 2 most confident:
[M]cat[M][M][M]mat
Step 2 — t=0.5→0.25, model predicts remaining masked, unmask 2 more:
Thecat[M][M]themat
Step 3 — t=0.25→0.0, unmask final 2:
Thecatsatonthemat
Final output (t=0.0):
Thecatsatonthemat

τ-leaping: unmasking multiple tokens per step

The exact reverse process unmasks one token per step (very slow for long sequences). τ-leaping is an approximation that unmasks multiple tokens per step — trading quality for speed.

Exact reverse: 1 token per step × L steps = L total steps τ-leaping: k tokens per step → L/k steps (k× faster) Quality vs speed: k=1 (sequential): best quality, slowest k=L (all at once): fastest, worst quality — tokens sampled independently, ignoring dependencies LLaDA default: k dynamically set by confidence threshold
04 — Why Bidirectional Attention

Why bidirectional attention is required

This is the most important architectural consequence of masked diffusion — and the root cause of why KV cache doesn't work.

The core problem with causal attention

Suppose we're predicting position 2 ("cat") in The [M] sat on the mat.

What the model sees to predict position 2: CAUSAL (autoregressive mask): Position 2 can see: "The" only Cannot see: "sat on the mat" → Very hard to predict "cat" without right context BIDIRECTIONAL (no mask): Position 2 can see: "The", "sat", "on", "the", "mat" → Obvious: "The ___ sat on the mat" → "cat"
With causal attention, predicting a masked token early in the sequence would be nearly impossible — it can't see the words after it. Bidirectional attention is logically required for masked prediction to work well.

Why this breaks KV cache

In autoregressive models, the KV cache works because old tokens' attention outputs don't change when new tokens are added — the causal mask prevents old tokens from attending to new tokens.

AUTOREGRESSIVE (causal mask): Step: generate token 51 Tokens 1–50: already generated, cached K,V Token 50's output A_50 = f(tokens 1–50 only) Adding token 51 does NOT change A_50 → cache valid ✓ BIDIRECTIONAL (no causal mask): Step: unmask token 30 (was [MASK], now "Paris") Token 29's K,V don't change (K_29 = x_29 · W_K, same) BUT token 29's output DOES change: A_29_before = f(... K_30=[MASK] ...) A_29_after = f(... K_30=K["Paris"] ...) → Every token's output is stale when any token changes → cache invalid ✗

This is why LLaDA cannot use a standard KV cache. Each denoising step requires a full O(L²) recompute of all attention.

Summary: causal vs bidirectional tradeoffs

PropertyCausal (Autoregressive)Bidirectional (LLaDA)
Context for predictionLeft side onlyAll tokens (left + right)
KV cacheYes — exact, O(L) per new tokenNo — full O(L²) every step
Fill-in-the-middleHard (no right context)Natural
Generation orderFixed left-to-rightAll positions simultaneously
Token dependencyHandled exactlyApproximated (independence assumption)
05 — Architecture & Training

Architecture and Training Objective

The transformer architecture

LLaDA uses a standard transformer — same as LLaMA — with one critical change: the causal mask is removed. Every token attends to every other token.

LLaDA-8B transformer block (same structure as LLaMA-3-8B): Input: x ∈ R^{L × D} (L tokens, D=4096 hidden dim) 1. RMSNorm(x) 2. Self-Attention (NO causal mask — fully bidirectional) Q = x W_Q, K = x W_K, V = x W_V A = softmax(Q K^T / √d) V ← all L×L attention scores 3. Residual: x = x + A 4. RMSNorm(x) 5. SwiGLU MLP 6. Residual Repeated 32 times (LLaDA-8B has 32 layers) Output: logits over vocabulary for each position

The model also receives the noise level t as conditioning — similar to how DiT conditions on timestep. This lets the model know how noisy the input is.

Special tokens

Sequence structure: [prompt tokens ...] [response tokens / [MASK] tokens ...] Prompt: never masked — always visible (prefix) Response: partially masked during training and inference [MASK] token: a dedicated embedding in the vocabulary → Not a word, just "something should go here"

Training objective (simplified)

At each training step:

1. Sample a clean text sequence x_0 2. Sample a noise level t ~ Uniform(0, 1) 3. Randomly mask each response token with prob t → get x_t 4. Run transformer: p_θ(x_0 | x_t) 5. Loss: cross-entropy at masked positions only L_MDM = E_t [ (1/t) · Σ_{i: x_t^i = [MASK]} -log p_θ(x_0^i | x_t) ] Intuition: "Given a partially masked sequence, predict the original tokens at masked positions." This is exactly BERT's Masked Language Modeling (MLM) but with a continuous masking rate t and weighted by 1/t.
The 1/t weight matters: at low t (few tokens masked), predicting them is easy but less informative. Weighting by 1/t upweights the harder, high-noise cases. In practice this simplifies to a standard cross-entropy objective over masked positions.
06 — Inference

Inference: Decoding Strategies

Given a prompt, LLaDA generates the response by running the reverse process — starting from all-masked response tokens and iteratively unmasking them.

Basic inference algorithm

def llada_generate(model, prompt, response_len, T=1024):
    # Start: prompt visible, response fully masked
    x = [prompt_tokens] + [[MASK]] * response_len

    for step in range(T, 0, -1):
        t = step / T                   # current noise level
        s = (step - 1) / T            # next noise level

        # Full forward pass: O(L²) attention over all tokens
        logits = model(x, timestep=t)  # shape: [L, vocab_size]

        # Compute confidence for each masked position
        confidence = softmax(logits).max(dim=-1)  # max prob

        # Decide which to unmask this step
        n_unmask = round((t - s) * response_len)    # proportional
        unmask_idx = topk(confidence[masked_positions], n_unmask)

        # Sample and lock in those tokens
        x[unmask_idx] = sample(logits[unmask_idx])

    return x[len(prompt_tokens):]

The decoding spectrum: quality vs speed

Response length L, T denoising steps, tokens unmasked per step k: Sequential (k=1): T = L steps, 1 token per step → Each unmasked token sees ALL previously unmasked tokens → Best quality, slowest Parallel (k=L): T = 1 step, all tokens at once → Tokens sampled independently — ignores dependencies → "full house" problem (incoherent combinations) → Fastest, worst quality LLaDA default (top-K per step): T ≈ L/K steps → Good balance but K is a fixed hyperparameter → LLaDA finds best results at small K (near-sequential)
The dependency problem: "The poker hand consists of two words: [M] [M]." Sampling position A independently might give "high", sampling position B independently might give "house". Combined: "high house" — not a valid poker hand. They should be sampled jointly ("full house", "high card") but the model only gives independent marginal probabilities.

Why LLaDA uses 1024 steps

For a 1024-token response: Ideal: unmask 1 token per step → 1024 steps needed With T=1024 and sequential decoding (top-1 per step): Each forward pass: O(L²) = O(1024²) ≈ 1M attention ops Total: 1024 forward passes → 1024 × O(L²) = 1 billion attention operations vs LLaMA generating same 1024 tokens: 1024 × O(L) with KV cache ≈ 1 million attention ops (1000× less)

This is the fundamental efficiency gap LLaDA faces vs autoregressive models. It's why acceleration is critical.

Why HumanEval is lower (~42% vs ~62%): Code generation has stronger sequential dependencies — earlier lines constrain later ones in a way that's harder to capture with bidirectional parallel decoding. This is also why acceleration is hardest for code: parallel decoding quality degrades most here.

The advantage: bidirectional context tasks

LLaDA particularly shines on tasks requiring global coherence and fill-in-the-middle reasoning. On some infilling benchmarks, LLaDA outperforms autoregressive models of similar size — because seeing both left and right context is a genuine advantage, not just an architectural curiosity.

08 — The Bottleneck

The Fundamental Bottleneck: Why LLaDA is slow

LLaDA is competitive in quality but dramatically slower than autoregressive models at inference. Here is exactly why.

Cost per generated token (LLaDA vs LLaMA)

Setting: generate 1024 tokens from a 256-token prompt L = 1280 total sequence length, D = 4096, H = 32 heads LLaMA-3-8B (autoregressive + KV cache): Per new token: Q @ K_cached^T = [1, 128] @ [128, L_so_far] Per new token ops: O(L_so_far · d) ≈ O(1280 · 128) = 163k FLOPs/head Total for 1024 tokens: 1024 × 163k × 32 heads ≈ 5.3B FLOPs LLaDA-8B (masked diffusion, T=1024 steps): Per step: full attention [L, L] = [1280, 1280] Per step ops: O(L² · d) = O(1280² · 128) = 209M FLOPs/head Total for 1024 steps: 1024 × 209M × 32 heads ≈ 6.8T FLOPs Ratio: 6.8T / 5.3B ≈ 1,280× more compute
Even with T=100 steps (lower quality), LLaDA is still ~128× more compute-intensive than LLaMA with KV cache. This is the gap that acceleration papers try to close.

The three sources of slowness

ProblemRoot CauseWhat's needed
No KV cacheBidirectional attention — any token change invalidates all outputsApproximate caching (Fast-dLLM / dKV-Cache)

This is why the reading order matters:
LLaDA (this paper) → establishes the quality baseline and the bottleneck.
dKV-Cache → approximate caching to fix problem 1.
Fast-dLLM → caching + parallel decoding to fix problems 1 and 2.
The research proposal → custom GPU kernels to fix problem 3: making the O(L²) step itself faster at the hardware level.

What makes LLaDA uniquely hard to accelerate

Image DiT (Chipmunk's target): - Fixed sequence length (all patches known at start) - Continuous noise → gradual change between steps - Active set (fast-changing K/V) is spatially coherent (voxels) - Sparsity pattern is stable for 5–10 steps LLaDA: - Fixed sequence length ✓ (same) - Discrete masking → token goes 0→1 abruptly (not gradual) - Active set = recently unmasked tokens (suddenly non-[MASK]) - Active set changes every step as new tokens are revealed - No spatial structure — token positions are arbitrary → Chipmunk's exact algorithm doesn't transfer directly. → Need to adapt: magnitude-based active set, re-anchor scheduling, and handle the discrete (not continuous) noise process.
