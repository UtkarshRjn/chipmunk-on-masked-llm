01 — The Problem

Why MDMs are 10–30× slower than AR LMs

Masked Diffusion Language Models (LLaDA-8B, Dream-7B, Mercury) generate text through a denoising process — starting with all tokens as [MASK] and progressively unmasking them over T steps. This is fundamentally different from autoregressive generation, and the difference is brutal for performance.

The inference loop

# MDM inference (LLaDA-8B, L=1024 tokens, T=128 steps)
x_1 = [MASK, MASK, ..., MASK]      # all L positions masked

for t in range(T, 0, -1):
    logits = model(x_t)             # full forward pass: BIDIRECTIONAL attention
    x_{t-1} = unmask_confident(x_t, logits)

return x_0                          # final answer

# Total work: T × O(L²) = 128 × O(1024²) = 128 × 1M ops = 134M
# AR with KV cache: O(L²) total. MDMs: O(T·L²) = 128× more.

MDMs — no KV cache possible

Bidirectional attention: every token attends to every other token. When ANY token unmasks, K and V for ALL tokens can shift.

Non-sequential order: any position can be chosen to unmask based on confidence. You can't pre-allocate next positions.

Result: O(L²) full recompute every step. 128 steps = 128× the work of AR generation for same-length output.

AR LMs — KV cache works perfectly

Causal attention: token i only attends to tokens 1..i. Once generated, K[i] and V[i] never change.

Sequential L→R order: next position always known in advance.

Result: O(L) per new token with KV cache. O(L²) total. 128× cheaper than MDM for same-length output at comparable model size.

The empirical escape hatch

If every K,V changed drastically at every step, there would be no hope. But dKV-Cache (Ma et al. 2025) measured something important:

Observation (dKV-Cache Figure 2): Once a token decodes (unmasks), its K,V representation stabilizes in subsequent steps. Masked tokens fluctuate. Decoded tokens: stable. This is the empirical foundation everything builds on.

This means across steps, only a small active set of positions has K,V that actually changed significantly. The rest can be cached. The question is: which positions are in the active set, and how do you compute attention on them efficiently?

02 — Prior Work Landscape

What exists — and where it stops

Two recent papers approximate the missing cache. Both are algorithmic-only, both run on older hardware, both explicitly invite further work.

FastDLLM (Wu et al. 2025 — NVIDIA, HKU, MIT)

Two-trick approach:

Trick 1 — Block-wise KV Cache: split response into blocks of B=32 tokens. Cache K,V for the prompt (PrefixCache) and optionally for the suffix [MASK] blocks (DualCache). Within a block's T decoding steps, only recompute the active block's K,V. Cache refreshes after each full block completes.

Trick 2 — Confidence-aware parallel decoding: unmask multiple tokens per step if their softmax confidence > τ=0.9. Theorem 1: if (n+1)ε ≤ 1, parallel greedy = sequential greedy. Averages 3.25 tokens/step, cutting steps from 1024 to ~315.

Results on A100: GSM8K (8-shot, gen=1024, DualCache): 27.6× ← memory-bound, long context HumanEval (0-shot, gen=1024): 3.7× ← compute-bound, short response GSM8K (5-shot, gen=256): 8.1×

The 27.6× is real but comes from a regime where memory bandwidth is the bottleneck (long prompt, long response). Code generation is compute-bound — the kernel has to actually do the FLOPs, and block-level caching doesn't help with FLOPs.

dKV-Cache (Ma et al. 2025 — NUS)

One-step delayed caching: when a token decodes (unmasks), don't cache its K,V immediately — wait one step. Why? The decode step is the step with maximum K,V change. Waiting one step lets the representation settle. Cache decoded tokens' K,V with periodic refresh every N=4–8 steps.

concat_reorder: at the start of each step, reorder the token sequence so decoded (cached) tokens are on the left and masked (recomputed) tokens are on the right. This makes K,V concatenation contiguous — no scatter gather needed.

Results on A6000 / H20: MMLU: 1.97× (near-lossless) GSM8K: 2.00× (accuracy improved: 72% → 77%!) HumanEval: 2.00× (accuracy improved: 19% → 39%!) GPQA (long prefill): 10–18× (prefix cache dominates)

The accuracy improvements (not just maintaining quality, but exceeding baseline!) suggest that full bidirectional attention every step may actually create noise that harms predictions. Caching decoded tokens provides a stable anchor.

03 — The Gap

Why kernel-level work is completely unclaimed

Every prior MDM acceleration method runs PyTorch operators on A100 or older hardware. The Hopper GPU (H100) has a completely new feature surface — cp.async for scattered HBM loads, TMA (Tensor Memory Accelerator) for contiguous loads, wgmma warp-group matrix multiply, and warp specialization for producer/consumer overlap. None of these have been characterized for MDM workloads. And Chipmunk — the paper that built exactly this kernel toolkit for image diffusion — explicitly does not mention MDMs as an application.

dKV-Cache (has the algorithm)

✓ Correct caching strategy (one-step delay)
✓ concat_reorder for contiguous access
✓ Works on A6000 / H20

✗ PyTorch-level ops only
✗ No cp.async scattered gather
✗ No wgmma tensor cores
✗ Recency heuristic, not magnitude
✗ No formal error bound

Chipmunk (has the kernel)

✓ cp.async scattered gather from HBM
✓ SRAM packing + dense wgmma
✓ Magnitude top-k active selection
✓ Voxel reordering
✓ H100-SXM5 benchmarked

✗ Built for image/video DiTs
✗ Output deltas, not K/V deltas
✗ Doesn't handle bidirectional cascade
✗ No MDM application mentioned

This proposal (the missing piece)

✓ Port Chipmunk's kernel to MDMs
✓ Magnitude-based K/V active selection
✓ Two-partition softmax (active + cached)
✓ Formal error bound (first in MDM lit)
✓ H100-SXM5 native

= dKV-Cache algorithm + Chipmunk kernel

The invitation — dKV-Cache §5 verbatim

"One primary limitation of this work lies in its focus on algorithmic design in isolation. While our proposed method introduces an effective caching mechanism from a purely algorithmic perspective, diffusion language models also exhibit substantial room for improvement at the system level. We believe that future research integrating algorithmic innovations with system-level optimization, such as memory management, parallelism, and hardware-aware execution, could unlock further efficiency gains and performance improvements for DLMs."

They wrote the gap statement. This proposal fills it.

04 — Five Contributions

What this proposal actually builds

1

Hopper kernel for mask-adaptive attention

The core engineering contribution. A custom CUDA kernel that splits K,V into two partitions every step:

ACTIVE PARTITION (small, ~25–40% of tokens)

Still-masked tokens + recently changed tokens. Gathered from scattered HBM positions via cp.async, packed contiguously into SRAM. Dense wgmma GEMM on the packed tile — tensor cores never know it was sparse.

CACHED PARTITION (large, ~60–75% of tokens)

Stable decoded tokens whose K,V hasn't changed. Stays in HBM in column-major chunks of 192 tokens. Loaded via TMA (Tensor Memory Accelerator) for fast contiguous reads.

Attention is computed across BOTH partitions via a two-pass online softmax — same technique as FlashAttention-3, but across two separate K,V sources instead of one.

// Pseudo-kernel structure
// Stage 1+2 — Pack active Q and K,V in parallel (warp specialization)
for k in 0..num_active:
    cp.async(Q_smem[k], Q_hbm + q_active_idx[k] * row_stride)
    cp.async(K_smem[k], K_hbm + kv_active_idx[k] * row_stride)

// Stage 3 — Two-pass online softmax across both partitions
attn_active = wgmma(Q_smem, K_smem, V_smem)           // active: SRAM
attn_cached = wgmma_with_tma(Q_smem, K_cache, V_cache)  // cached: HBM via TMA
output = combine_softmax(attn_active, attn_cached)

// Stage 4 — Async writeback to HBM
cp.async.bulk_store(out_hbm + q_active_idx, output)
Target: 60–75% of FlashAttention-3 dense throughput at 70% active-set sparsity → ~2–3× per-step speedup vs full dense recompute. Implemented in ThunderKittens DSL.
2

Magnitude-based active subset selection

dKV-Cache uses recency as the signal: once a token decodes, wait one step, then cache. This is correct but weak — it doesn't capture positions whose K,V is still shifting despite being long-decoded.

This proposal uses a hybrid magnitude + recency signal (same philosophy as Chipmunk's top-k by column-sum magnitude for image DiTs):

Active set A_t = A_recent ∪ A_magnitude A_recent = still-masked positions ∪ decoded in last R=2 steps (worst-case safety: newly unmasked must be recomputed) A_magnitude = top-k by ||K_t^pred − K_{t-1}|| (cheap proxy) (captures old tokens whose representation is still drifting) |A_t| ≈ 25–40% of L (target sparsity)
dKV-Cache Figure 2(c) showed that the largest K,V changes happen at the decode step — they observed the magnitude signal but used it only as motivation. Chipmunk used magnitude for output deltas in images. Nobody has used it for K,V deltas in MDMs. This is a genuine novel contribution.

Cheap proxy for magnitude: compute norm of a single-layer feature or early-exit from layer 4 of the 32-layer model. Amortize cost across multiple steps. Chipmunk's approximate top-k gives 3.42× speedup over PyTorch top-k for the selection itself.

3

Periodic dense re-anchor with formal error bound

Using a sparse active set introduces approximation error — if a position should be in the active set but isn't, its K,V update is skipped, causing downstream attention to use a stale value. This error accumulates across steps.

The fix (same as Chipmunk's "dense anchor"): every M=7 denoising steps, run a full O(L²) dense bidirectional attention. This resets all accumulated error to zero and refreshes the cache with exact K,V values.

Per-step error: err_step ≤ C₁·τ + κ_softmax·ε_numeric Accumulated error (M sparse steps): err_M ≤ M · err_step · G_bidirectional^step where G = cascade amplification factor (bidirectional feedback) After re-anchor step: err = 0 (exact reset)
The G_bidirectional term is the hard part. In image diffusion, errors are visually imperceptible and bounded trivially. In text, an error at position i shifts attention output at j, which feeds back at the next step. The formal proof bounds G using attention sharpness (max attention weight < α < 1 → cascade is contractive → geometric convergence). This is the first formal error bound in the MDM acceleration literature.

Anchor period sweep: M ∈ {3, 5, 7, 10, 15, 20}. Chipmunk uses M=10 for images; expected MDM sweet spot M=5–10 based on dKV-Cache's refresh rate of 4–8.

4

Hopper-native characterization (nobody has done this)

Neither FastDLLM nor dKV-Cache tested on H100. The Hopper GPU (H100-SXM5) has specific features that significantly change performance characteristics:

Hopper features this proposal uses:

  • cp.async — scattered HBM loads, multiple in-flight
  • TMA — Tensor Memory Accelerator for contiguous chunks
  • wgmma — warp-group matrix multiply (4th-gen tensor cores)
  • Warp specialization — producer/consumer overlap
  • Async barrier for softmax reduction across warps

Why this matters:

cp.async is what makes scattered gather cheap. On A100 you'd have to serialize the loads or use slower memory ops. On H100, you issue all K scattered loads simultaneously, they arrive in parallel, you pack them — all overlapped with the TMA load of the cached partition.

Even just running FastDLLM and dKV-Cache on H100 (which nobody has done) is a useful contribution that characterizes the opportunity.

5

Three-layer stacked acceleration

The three orthogonal speedup levers compose multiplicatively:

Layer 1 — Block level
FastDLLM
Block-wise KV cache (PrefixCache + DualCache) + confidence-aware parallel decoding. Coarse caching. High-impact in memory-bound regime.
Layer 2 — Position level
This Proposal
Within each FastDLLM block, only recompute the active subset's K,V via cp.async gather + wgmma. Reduces actual FLOPs, not just memory I/O.
Layer 3 — Step level
DualDiffusion-style
Speculative decoding with a small drafter + large verifier. Layer 2 makes the verifier ~2× faster. DualDiffusion currently fails on GSM8K — the error bound from C3 may fix this.
The composability story is strategically important: it sidesteps "do we beat FastDLLM" entirely. This proposal includes FastDLLM as a component. The question becomes "how much does the kernel-level work add on top" — which is a cleaner, more defensible comparison.
05 — End-to-End Algorithm

How it all fits together per denoising step

EACH DENOISING STEP t: Is this a re-anchor step? (t % M == 0) YES → Full O(L²) dense attention. Recompute all K,V. Refresh entire cache. Update drift proxy. Cost: expensive but resets error to 0. NO → Sparse step. 1. Determine active set: A_recent = still-masked ∪ decoded in last 2 steps A_magnitude = top-k drifters by proxy magnitude A_t = A_recent ∪ A_magnitude (~25–40% of L) 2. Attention kernel (two-partition): Gather A_t's K,V from HBM → SRAM (cp.async, parallel loads) Load cached partition K,V from HBM via TMA (contiguous chunks) Compute attention via two-pass online softmax across both partitions Write output to HBM (async store) 3. MLP kernel: Run MLP only for still-masked positions + active set (predictions only needed at mask positions; active set needs update) 4. Predict: Run LM head at masked positions → confidence scores Unmask positions with confidence ≥ τ (FastDLLM parallel decode) 5. Update cache: Commit new K,V for A_t positions back to HBM cache Update drift proxy for next step's magnitude selection

Key nuances that make this non-trivial

RoPE under permutation

Rotary position embeddings bake the position index into Q and K. You can't freely reorder tokens then apply RoPE. Fix: carry position indices alongside packed rows, apply RoPE after gather. dKV-Cache appendix confirmed this is feasible.

Two-partition softmax

Standard FlashAttention computes softmax over one contiguous K. Here K is split: active (in SRAM) and cached (in HBM). Two-pass online softmax: compute partial (m, l) for each partition, then combine with the standard FlashAttention reduction formula.

Voxel reordering

Chipmunk reorders tokens into spatial voxels of size C=192 so each chunk shares one sparsity pattern. For MDMs: reorder by mask-state (all still-masked together, all decoded together). This reduces approximation error ~2× vs unstructured sparsity at the same compute budget.

06 — Theoretical Analysis

The formal error bound — why MDMs are harder than images

Image diffusion errors are visually imperceptible — even large approximation errors don't change the perceptual output. Text is completely different: an error in K at position i can change the attention output at position j, which changes what token gets predicted at position j, which changes the entire downstream generation.

The bidirectional cascade

If K[i] has error ε at step t:

Shift in attention output at j: ≈ ε · (attn_weight[j→i]) · ||V[i]|| This propagates: K[j] at step t+1 depends on the attention output at j, which just shifted. Cascade: ε → ε·α → ε·α² → ... where α = max attention weight < 1

If α < 1 (attention is not fully concentrated on one position), the cascade is contractive — errors shrink geometrically rather than exploding. The bound holds.

The bound (informal)

Inputs: τ = magnitude threshold M = anchor period α = max attention weight Per-step error: err_step ≤ C₁·τ + ε_numeric Cascade amplification: G ≤ 1/(1−α) (geometric series) M-step accumulated error: err_M ≤ M · err_step · G After anchor: err = 0 (exact reset)

A formal version of this lets you set M and τ from a target error rate rather than sweeping empirically. First such bound in the MDM acceleration literature.

Why even a loose bound matters: DualDiffusion's heuristic verification rules (KL-divergence threshold, confidence threshold) have zero theoretical grounding — they fail on GSM8K. A formal bound, even loose, establishes that the method can preserve quality with appropriate hyperparameters, and identifies what assumptions are load-bearing. That's a genuine contribution even before the bound is tight.

Estimated theoretical work: 3–4 weeks

Follows established techniques from sparse attention literature (Performers' approximation analysis, Reformer's LSH analysis). The proof template is known — the new work is applying it to the bidirectional cascade structure unique to MDMs.

Why HumanEval and RULER are the headline benchmarks

FastDLLM gets only 3.7× on HumanEval

HumanEval is compute-bound: the response is code (moderate length), and the bottleneck is FLOPs, not memory bandwidth. Block-wise caching reduces memory I/O but doesn't reduce FLOPs. FastDLLM saturates at 3.7×.

This proposal reduces actual attention FLOPs by operating at the position level (70% of positions skipped). That directly attacks the compute-bound bottleneck FastDLLM can't touch.

RULER 8K–32K is where O(L²) really bites

RULER is a long-context benchmark. At L=32K, the dense attention matrix is 32K×32K = 1B entries per step. Even 70% sparsity reduces this to 300M — a real reduction, not a rounding error.

No existing MDM acceleration paper has run long-context benchmarks. This is the greenfield territory where the expected speedup is highest.
