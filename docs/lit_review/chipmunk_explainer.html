01 — The Problem

DiT inference is brutally expensive

HunyuanVideo (13B parameters, 118k token sequence) takes 18 minutes on an H100 to generate a 5-second video — because diffusion runs 50 sequential forward passes, each with full attention over all tokens.

Standard DiT: no reuse

Each of the 50 steps computes:

  • Full attention: O(N²) over 118k tokens
  • Full MLP: O(N·F) every layer
  • Zero reuse of any computation across steps
Every step: full compute. Even if 90% of the work produces the same result as the previous step.

Key empirical observation

Between consecutive denoising steps, the latent vector changes slowly. Most intermediate activations barely move:

  • Attention: 5–25% of values explain 90%+ of change
  • MLP: 15–25% of neuron columns explain 70%+ of change
Cache the stable 75–95%. Recompute only the fast-changing 5–25%.

02 — Core Insight

The shared form: act(a @ b) @ c

Chipmunk's central observation: attention and MLP share exactly the same computational skeleton — both produce a weighted sum of vectors.

Attention: output = softmax( Q @ K^T ) @ V = act(a @ b) @ c MLP: output = GeLU( X @ W_1 ) @ W_2 = act(a @ b) @ c

In both cases, act(a @ b) produces scalar weights for each column-vector in c. The output is a linear combination of those vectors. Each scalar picks how much of one vector goes into the output.

What a "sparse delta" is

Between step t−1 and step t, only a small subset M of those vectors (columns of K/V or W₁/W₂) changes significantly. Call that the active set.

o_t ≈ o_{t-1} − [act(a_{t-1} @ b_{t-1}) * M] @ c_{t-1} (remove old active contribution) + [act(a_t @ b_t ) * M] @ c_t (add new active contribution) = o_cache + ΔO_sparse

Everything outside M is reused from the cache — zero recomputation.

Left — Sparse Cross-Step Deltas

The latent vector traces a path in high-dimensional space across 50 steps. Each step = one direction change. Chipmunk tracks which individual output vectors in attention/MLP change direction fastest and only recomputes those.

d = act(a @ b) @ c Step t-1: d_{t-1} = Σ_j α_j^{t-1} · c_j Step t: d_t ≈ d_{t-1} − Σ_{j∈M} α_j^{t-1} · c_j^{t-1} ← remove old + Σ_{j∈M} α_j^t · c_j^t ← add new M = active set (top-k by magnitude change)

In the figure: the orange arrows (cached activations) flow straight between steps. Only the active set (Step 2, green) gets fresh computation. Sparse deltas replace the fastest-changing vectors and reuse the rest.

Cache I/O runs on separate warps while MLP second layer computes.

Result: sparsity pattern ID and cache updates are effectively free — hidden inside existing compute via warp specialization.
04 — The Kernel

Column-Sparse Gather: HBM → SRAM

Standard GPU kernels (FlashAttention, cuBLAS) load contiguous chunks from HBM. Chipmunk's active set is arbitrary positions scattered across HBM. The fix: cp.async per-thread independent loads into a contiguous SRAM buffer.

What are the 118,000 tokens? (not video history)

Common confusion: in GPT, each token attends to its past history (causal). DiT is completely different — the entire video is denoised at once. All frames exist in the latent simultaneously from the very first step.

HunyuanVideo token layout: T frames × H patches × W patches ≈ 80 × 45 × 80 → ~288k positions → compressed to 118k tokens Token (t=0, h=5, w=10) = patch at frame 0, position (5,10) Token (t=60, h=5, w=10) = same spatial position, frame 60 Both exist simultaneously in the latent. Every token attends to every other token (no causal mask). "All tokens" = all space + all time in the video, right now.

Across the 50 denoising steps, the latent gradually gets cleaner — that is the only "temporal history." Inside any one step, attention sees the full video at once.

Q, K, V shapes — normal dense vs Chipmunk sparse (one attention head)

The [118k × 118k] score matrix is recomputed 50× per video, across all layers and heads. At 18 min on H100, this is the bottleneck.

Chipmunk sparse (5% active)

k = 5% × N = 5,900 d = 128 Q : [N, d] = [118k, 128] unchanged — need all queries K : [N, d] stored in HBM gather k rows → K_idx : [k, d] = [5.9k, 128] V : [N, d] stored in HBM gather k rows → V_idx : [k, d] = [5.9k, 128] ─── sparse computation ──────────────────────── delta_scores = Q @ K_idx^T [N,d] @ [d,k] → [N, k] = [118k,128] @ [128,5.9k] → [118k, 5.9k] = 696M entries (vs 13.9B) → 20× smaller ✓ weights = softmax(delta_scores / √128) [N, k] ΔO = weights @ V_idx [N,k] @ [k,d] → [N, d] O = O_cache + ΔO ← add sparse delta to cache cost: O(N · k · d) per head
Q stays full [N, d] — every token still asks its own question. Only K and V are reduced: Chipmunk gathers just the k=5% of key/value vectors that changed most since the last dense step.
Why Q stays full but K, V shrink: Q = "what am I searching for?" — every token needs to ask its own question, so Q cannot be reduced. K = "what do I offer?" and V = "what do I give?" — Chipmunk identifies which K/V positions changed most (the active set M) and gathers only those rows from HBM into a packed SRAM tile. The multiplication Q @ K_idx^T scores each query against only the active keys. Everything else reuses the previous step's output via O_cache.

Why unstructured sparsity is slow

GPU tensor cores need at least 64×64 tiles in SRAM to achieve peak throughput. Unstructured [1,1] sparsity produces tiny scattered tiles — tensor cores starve.

Unstructured: active positions scattered everywhere
Cannot form 64×64 tile → tensor cores idle

Select whole columns of K/V or W matrix. Gather them (scattered in HBM) into a contiguous SRAM tile. Tensor cores see a normal dense tile.

Block sparsity vs Column sparsity — the tradeoff

Block sparsity skips whole 192×128 tiles (fastest) but each tile may contain many stable positions — high approximation error. Column sparsity selects exactly the columns that changed most — 2× better accuracy at similar speed.

05 — Voxel Reordering

Why token order matters for approximation quality

Column sparsity means a contiguous chunk of C=192 tokens shares one sparsity pattern — they all activate the same K/V columns. For this to be accurate, tokens in the same chunk should be spatially similar (attend to the same things).

Default: raster order

Tokens laid out left→right, top→bottom, frame 1 then frame 2... A chunk of 192 spans a horizontal strip. Tokens at opposite ends of the strip may have very different content — shared sparsity pattern is inaccurate.

Voxel order (Chipmunk)

Reorder tokens so each chunk of 192 = a 3D cube (voxel) of spatially nearby pixels across frames. Pixels in the same small 3D region have similar color/texture → similar attention patterns → shared sparsity is accurate.

Voxel reordering improves attention approximation quality by 1.2× (2× for MLP, negligible — MLP sparsity doesn't depend on spatial locality the same way). Applied once at generation start, reversed before VAE decode. Zero extra compute. 
# Voxel reordering — one-time permutation at start of generation
def voxel_reorder(tokens, T, H, W, vt=4, vh=2, vw=2):
    # tokens: [T, H, W, D] in raster order
    tokens = tokens.reshape(T//vt, vt, H//vh, vh, W//vw, vw, D)
    # Permute so dim-0 = voxel index, dims-1,2,3 = within-voxel
    tokens = tokens.permute(0, 2, 4, 1, 3, 5, 6)
    return tokens.reshape(-1, D)
    # Now contiguous chunk of C=192 = one voxel = spatially local

Dense Step — Attention

Run full FlashAttention. Then compute a column-sum — for each voxel of 192 tokens, sum how much total attention probability it assigns to each key position. Top-k over this gives the most-attended keys per voxel.

D[voxel_i, key_j] = Σ_{q ∈ voxel_i} softmax(Q @ K^T)[q, j] idx[voxel_i] = TopK_k( D[voxel_i, :] ) ← cached for sparse steps O_cache = O_dense − softmax(Q @ K_idx^T) @ V_idx ← enables additive deltas

Column-sum is fused into the FlashAttention kernel — no extra pass. Top-k uses an approximate bucket-based kernel (3.42× faster than PyTorch topk).

Sparse Step — Attention

Only recompute the k keys/values identified in the last dense step. Gather them from scattered HBM positions via cp.async, pack into SRAM, run wgmma.

ΔO = softmax( Q @ K_idx^T ) @ V_idx O = O_cache + ΔO Complexity: O(N·k) not O(N²) At 5% active (HunyuanVideo): k = 0.05N → 20× fewer FLOPs

Dense Step — MLP

Run full MLP. Cache three tensors for the sparse steps to come:

  1. T_m — tile-mean pre-activation per voxel: cheap proxy for which neurons change
  2. A_cache — full GeLU activation tensor
  3. M_cache — full MLP output (so deltas can add to it)

Sparse Step — MLP

Compute tile-mean of current activations and compare to cached tile-mean to find which neuron columns changed most. Only compute those.

Δt_m = |T_current − T_m_cached| ← cheap: tile-means, not full activations idx = TopK_k( Δt_m ) ← k neurons that changed most per voxel ΔM = GeLU(X @ W1_idx − A_cache_idx) @ W2_idx O = M_cache + ΔM

The subtraction − A_cache_idx is the delta (only recompute what changed). Cache writeback overlaps with W₂ matmul via warp specialization.

End-to-end pseudocode

def chipmunk_inference(model, noise, steps=50, M=10):
    x = voxel_reorder(noise)              # once at start
    attn_cache = mlp_cache = None

    for t in range(steps, 0, -1):
        if t % M == 0:                     # dense anchor every M steps
            Q, K, V = model.qkv(x, t)
            O_dense  = flash_attention(Q, K, V)      # full O(N²)
            col_sum  = column_sum_fused(O_dense)      # fused — free
            idx_attn = approx_topk(col_sum, k=attn_k)
            attn_cache = build_attn_cache(O_dense, Q, K, V, idx_attn)

            A_full   = gelu(x @ W1)
            T_m      = tile_mean(x @ W1, C=192)
            mlp_cache = (T_m, A_full, A_full @ W2)

        else:                               # sparse step
            # Attention: gather active K,V → pack → wgmma
            K_idx, V_idx = cp_async_gather(K, V, attn_cache.idx)
            delta_O = wgmma(Q, K_idx, V_idx)
            O = attn_cache.O_cache + delta_O  # O(N·k)

            # MLP: tile-mean diff → top-k neurons → sparse compute
            T_m_new = tile_mean(x @ W1, C=192)
            idx_mlp = approx_topk(|T_m_new - mlp_cache.T_m|, k=mlp_k)
            delta_M = sparse_mlp(x, W1, W2, idx_mlp, mlp_cache.A)
            O_mlp   = mlp_cache.M_cache + delta_M

        x = apply_residual(x, O, O_mlp)

    x = voxel_unreorder(x)               # reverse before VAE
    return vae.decode(x)
07 — Kernel Fusion

Hiding the overhead of dynamic sparsity

Without fusion, identifying the active set (column-sum, top-k) and maintaining the cache would add ~3× overhead per sparse step. Chipmunk fuses everything to near-zero cost.

OperationUnfused baselineFusedSpeedup
Attention + column-sum2 separate passesFused into single attention kernel3.26×
MLP + cache writebackSequentialOverlapped with W₂ matmul (warp-spec)1.41×
Mask → indices conversionSeparate kernelFused with column-sum kernel1.39×
Top-k selectionPyTorch torch.topkApproximate bucket-based top-k3.42×
The approximate top-k uses bucket counting (histogram) to find the k-th largest threshold, then selects all elements above it. This gives 3.42× speedup over exact sorting with negligible accuracy loss on sparsity pattern selection.
Warp specialization: on an H100 SM, Chipmunk dedicates some warps to data loading (cp.async gather of active K/V from HBM) and other warps to compute (wgmma tensor-core GEMM). Producer and consumer warps run in a pipeline — compute never stalls waiting for memory.

Why Chipmunk sometimes improves quality

At ~90% attention sparsity, Chipmunk focuses attention on the most-attended keys — which tend to correspond to the subject of the prompt. Human-preference metrics (ImageReward) and CLIP reward subject-prominent generations.

Failure mode: backgrounds can appear slightly blurred, because background tokens are deprioritized by the sparse attention pattern (fewer attention weights pointing to them).

Composability — stacking with other methods

Chipmunk operates at within-step, within-layer granularity (individual K/V vectors). It is orthogonal to and stacks naturally with:

• Step caching (TeaCache) — skip whole steps ✓
• Layer caching (BlockCache) — skip whole layers ✓
• Token caching (ToCa) — skip whole tokens ✓

The stacking is native because Chipmunk's caches live at finer granularity than any of these — they don't interfere.
09 — Summary

The full picture

Three-sentence summary

Between any two consecutive denoising steps in a DiT, only 5–25% of the K/V vectors in attention (and neuron columns in MLP) change significantly — the rest can be safely reused from cache without perceptible quality loss.

Chipmunk identifies this active set dynamically per step using magnitude-based top-k (column-sum over attention probabilities; tile-mean delta for MLP), then uses cp.async scatter-gather to pull those scattered vectors from HBM into a packed SRAM tile, giving tensor cores a dense tile to operate on at full utilization despite the underlying sparsity.

The overhead of identifying the active set and maintaining the cache is fused into existing compute via warp specialization, making bookkeeping effectively free — delivering 9.3× attention kernel speedup and 2.16–3.72× end-to-end on state-of-the-art video DiTs with near-lossless quality.

Limitations (honest)

  • Large models only. Optimal for compute-bound DiTs (HunyuanVideo 118k seq, FLUX 4.5k). Smaller models: sparsity overhead dominates savings.
  • Few-step models. If T=4 instead of 50, activations change more aggressively per step → less opportunity for caching.
  • Background quality. ~90% sparse attention concentrates on subjects → backgrounds can appear slightly soft.
  • Training-free only. Future work: integrate sparse recomputation into training so models learn to exploit it even more aggressively.
